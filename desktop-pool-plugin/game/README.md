# 桌面台球 · 黑八（3D）

浏览器里直接跑的美式 8 球，纯 3D、纯程序化素材、无外部依赖。
双击 `index.html` 就能玩（`file://` 也行，不用起服务器）。

---

## 打开方式

**直接双击 `index.html`** 即可（`file://` 可用）。

> 关键：`index.html` 引用 `bundle.js` 时**必须用普通 `<script>`，不能用 `type="module"`**。
> `type="module"` 在 `file://` 下会被浏览器按 CORS 规则拦掉，表现为纯黑屏、控制台里只有一行
> `Access to script ... blocked by CORS policy`。本项目已改为普通 script。

页面内置启动守卫：如果 `bundle.js` 因路径错误或被拦截而没执行，5 秒后会显示
「游戏未能启动」并在提示里给出排查方法，**不会再留一个无提示的黑屏**。

## 规则（WPA 标准 8 球）

- **开球**：母球置于开球线（头线）之后，把球堆打散。开球进球不换手。
- **分组**：第一杆合法进球后确定花色——全色 1–7 或花色 9–15。
- **犯规**（对手获得**手中球**，可自由摆放母球）：
  1. 母球落袋
  2. 母球先碰到错误的球（开放台面不能先碰 8 号；分组后须先碰本组）
  3. 空杆（没碰到任何球）
  4. 没进球且碰球后没有任何球吃库
  5. 提前打进 8 号（本组未清完）
- **获胜**：清完本组后合法打进 8 号。提前打进 8 号或打 8 号时同时犯规 → 判负。

## 物理

参数取自真实台球模型（`pooltool` 与 `tailuge/billiards` 的实测值，源自 Han 2005 / Mathavan 2007 / Stronge 的碰撞理论）：

| 量 | 值 |
|---|---|
| 球半径 / 质量 | 28.575 mm / 170 g（2.25 in 标准） |
| 滑动摩擦 μ_s | 0.20 |
| 滚动摩擦 μ_r | 0.0125 |
| 球-球恢复系数 | 0.95 |
| 库边恢复系数 | 0.85 |
| 台面 | 9ft 比赛台，2.54 × 1.27 m |

实现上的几个关键点：

- **三段式摩擦**：滑动（接触点相对速度 u≠0）→ 滚动（u=0，纯滚动约束）→ 竖直自旋独立衰减。
  低杆能拉回、高杆能跟进、左右塞吃库后变线，都是这个模型的自然结果，不是特判。
- **固定步长 + 自适应子步**：每步按最快球的位移拆子步，保证单子步位移 < 0.45R，9 m/s 也不穿库。
- **球-球切向冲量**：产生真实的 throw 偏移（薄球时目标球会略微跑偏）。
- **库边接触点高于球心**（0.30R）：撞库时产生回旋，球会"咬"一下库边。

## 自检

```bash
node selftest.mjs        # 26 项物理/规则断言
node gametest.mjs 10     # 10 局 AI 自动对战，验证规则不会卡死
node build.mjs           # 重新打包 bundle.js
```

当前结果：

- `selftest.mjs` → **26 / 26 通过**
  （含：滚动距离合理、正碰动量传递、库边反弹系数、落袋、低杆回拉、高杆跟进、
   9m/s 不穿库、60fps 与 144fps 结果一致、动能不异常增长、静止后不漂移、
   空杆/母球落袋/先碰错球/无球吃库判罚、分组判定、8 号球胜负、手中球合法性）
- `gametest.mjs` → **10 / 10 局正常结束**，平均每杆 0.6 球，犯规率约 30%

## 音效

全部用 Web Audio 实时合成，**没有任何音频文件**：

- 球-球：宽带撞击 + 1.8k/3.2k/4.6k Hz 三个高 Q 模态 + 150–250 Hz 体感低频，
  速度和亮度随撞击速度变化，每次调用有 ±3% 随机化，连打不会像复读机
- 库边：低通噪声 + 120 Hz 闷响（比撞球暗得多）
- 皮头击球：瞬态 + 木质敲击（180/420 Hz）+ 皮革中频
- 落袋：塑料碰撞 + 220→70 Hz 下坠 + 低频余响
- 犯规/进球/胜负：短促提示音
- 母线经压缩器 + 软削波，再走共享卷积混响（程序化生成 1.6s 脉冲响应）

## 改手感

全部在 `src/config.js`：

```js
physics.uRoll      // 台布速度：越大球停得越快
physics.eCushion   // 库边弹性：越大越"脆"
physics.uSpin      // 塞的衰减速度
camera.aimDistance // 瞄准视角离母球多远
gameplay.aiSkill   // 对手准度 (0..1)
```

改完跑 `node build.mjs`，再跑一次 `node selftest.mjs` 确认没弄坏物理。


## 瞄准精度

瞄准不再用"光标射线打台面"（那种做法在光标靠近母球时，1px 能差 0.5°，根本没法微调），
改成**按鼠标增量旋转瞄准角**，精度只取决于像素增量本身。

实测可达精度：

| 操作 | 最小角度变化 |
|---|---|
| 鼠标 1px（普通） | 0.0637° |
| 鼠标 1px（Shift 精调） | 0.0159° |
| <kbd>←</kbd>/<kbd>→</kbd> | 0.1003° |
| <kbd>Shift</kbd>+<kbd>←</kbd>/<kbd>→</kbd> | 0.0100° |
| <kbd>,</kbd>/<kbd>.</kbd> | 0.0010° |

Shift 精调时，画面中下方会显示实时角度读数（如 `68.766°`），让 0.01° 的调整可见。

参考量级：球-球接触点偏移 **0.5 mm → 目标球方向偏 0.5°**，
所以 0.01° 的瞄准精度对应约 **0.01 mm** 的接触点控制，远超人手需要。
